# RVE UI仕様 v1.1

対象はRVE v1.0の個別銘柄・ポートフォリオ画面。数理定義は [`rve-v1.0-spec.md`](rve-v1.0-spec.md) を正本とし、UIの都合で指標値や価格系列を変更しない。正規化基準の欠損値選択は、同正本の第5節に定義する。

## 1. 分析の見せ方

画面は次の意味を区別する。

| 概念 | 指標 | 主な表示 |
|---|---|---|
| アンカー感応度 | 5アンカーβ | 実測βの符号付き5軸レーダーと数値一覧 |
| リスク水準 | σ、ES | 独立した数値カード |
| 過去分布に対する相対的位置 | 7指標の正規化値 | 直近52週の指標別時系列 |

βは感応度で相関係数ではない。σは年率変動性、ESは損失上位8週の符号付き平均であり、相互に代用しない。正規化値は自身の履歴に対する相対位置であって、絶対リスク・売買シグナル・予測ではない。

## 2. 個別・ポートフォリオ画面

個別銘柄とポートフォリオは別タブとする。個別画面は銘柄・基準日・データ品質、β感応度、σ/ES、過去推移、算出条件・出所の順に表示する。ポートフォリオ画面は合成ベクトルを表示し、分析モード、構成銘柄・ウェイト、観測数、無効週を示す。個別銘柄の指標を加重平均してポートフォリオの結果にしない。

ポートフォリオ未設定は未設定と表示し、ゼロ値やサンプル値を使わない。実績ウェイト分析と現在ウェイトのシナリオ分析を区別する。

## 3. β感応度レーダー

5軸はGold `1540.T`、US Equity `^GSPC`、Japan Equity `1306.T`、US Treasury `TLT`、Japan Bond `2510.T`。各軸はRVE v1.0の52週βを実測値のまま表示する。アンカーは資産クラスのプロキシである旨を示す。

各βを `[-3,+3]` にクリップして描画半径だけを求める。描画半径Rに対し、線形写像を `r/R = (clip(β,−3,+3)+3)/6` とする。したがって中心は−3、ゼロ基準リングはR/2、外周は+3を表す。全軸で同じ尺度・方向を使い、−3・0・+3を示す。中心がβ=0であるとの誤解を避ける凡例を置く。

正βと負βは外側/内側の位置に加え、色・数値符号でも区別する。β=0はゼロリング上に表示する。範囲外はクリップ状態を示し、レーダー脇の表に元の実測値、状態、推定52週、観測数を表示する。計算不能の軸は点・線を描かず、残りの軸をゼロで補完しない。全軸が有効でない限り、面積を塗りつぶして総合スコアのように見せない。

## 4. リスク水準

- **年率変動性（σ）**: 直近52週の週次単純リターン標本標準偏差に `√52` を掛け、年率%で表示する。
- **ES 95%（損失上位8週の平均）**: 直近156週の損失 `−R` の上位8値の符号付き平均を%表示する。負値を反転・ゼロ丸めしない。

各カードに状態、推定窓、観測数を示す。ESの符号付き定義と、σとESの意味の違いを説明する。

## 5. 相対的位置と時系列

正規化は `z=(x−median(H))/IQR(H)`、`IQR=P75−P25` とする。Hは対象週より前から遡った直近52個の有効な指標値。無効な週は飛ばして有効値を集め、対象週の値を混ぜない。必要数に達しない場合は未算出状態を返す。IQRが設定閾値以下の場合はnullとし、算出不足とIQR不足を区別する。

グラフは直近52暦週の週次行を保ち、null区間を詰めず線を切る。7指標の正規化値を指標別の小グラフに表示し、各グラフに基準日・状態・目盛りを付ける。別の5グラフで生βの推移を表示し、正規化βと重ねない。各小グラフのスケールは独立であり、銘柄・指標間の絶対値比較には使わない。

## 6. 出力契約

最新結果の `asset` と `portfolio` は維持する。追加の `asset_history` と `portfolio_history` は、直近52暦週の時系列を古い順に保持する。各要素は既存ベクトルと同じ `as_of` および7指標を持ち、各指標は `value`, `status`, `normalized`, `normalization_status`, `window_weeks`, `observation_count` を持つ。βの観測数は有効な資産・アンカーのペア数。

履歴の各週について計算不能の値はnullと状態で保持する。ポートフォリオ未設定なら `portfolio` と `portfolio_history` はnull、状態は `not_configured` とする。設定済みならモードと保有比率を表示可能なメタデータとして出力する。これらの履歴・メタデータ追加は、σ・ES・β・週次リターンの計算式を変更しない。

## 7. データ状態

`ok`, `insufficient_history`, `missing_price`, `missing_fx`, `invalid_price`, `zero_variance`, `iqr_below_threshold`, `configuration_error`, `calculation_error`, `not_configured` を表示上区別する。nullまたはok以外は有効値として描画しない。1指標の失敗で他の有効指標を隠さない。

## 8. 検証要件

- レーダー: 全正、正負混在、全負、ゼロ、±3境界、範囲外、null/エラー軸を検証する。
- 指標・時系列: σ/ESの単位・符号、正規化対象週の除外、無効週を飛ばして有効52値を集めること、IQR不足、null区間、生βとzβの分離を検証する。
- ポートフォリオ: 実績・シナリオの識別、ウェイト、欠損週、未設定を検証する。
- ブラウザ: 実データJSONとテスト用JSONを使い、デスクトップ・狭幅画面、コンソール、JSON取得失敗を確認し、スクリーンショットと実行記録を監査資料に保存する。
